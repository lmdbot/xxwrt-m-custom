# 06 · UI/UX 落地计划与验收

## 0. 当前状态

- 本目录是用户要求的**设计提案/交付资料**；本次不授权改动生产 APP 代码。
- 当前主线已存在 3.0 五底栏候选实现；本计划在该实现上做信息架构与交互收敛，避免重复重写核心 RPC/UCI。
- 设计源基线：`main@10a06af2a0`，代码更新后先复核本设计中的入口归属、操作前置条件和测试。
- 本目录效果图使用示例设备与速率，不是 APK 运行截图；上线前必须以实际截图替换/补充。

## 技术迁移建议

- **路由统一**：以每个 `deviceId` 为作用域的 `NavigationState`（`tab,route,params,origin,scroll`）；先兼容原有 `toolPanel`，再逐步组件路由化。
- **功能注册表**：`featureCatalogV3.js` 保持唯一权威入口；收藏和搜索从注册表映射，禁止生成多套 ID。
- **设计 Token**：将 `style-v3.css` 的颜色/间距沉淀为语义变量；分层后只需替换组件外壳，减少大规模 CSS 覆盖。
- **组件迁移**：先复用已验证的 RouterAppsPanel、RouterOperationsPanel 等内部服务操作，统一页头与状态，后续再拆分更细的视图。
- **测试增量**：每迁移一个功能必须保留原操作模拟用例，新增 UI 截图基线及后退/权限/离线验证。

## 范围外事项

不新增并不存在的 OpenClash Controller 控制、持续后台采样服务、真实拓扑推断保证、任意防火墙规则编辑器或新的设备远程命令权限；这些需要独立产品与技术评审。设计原型中出现的示例数字/状态不构成能力承诺。
