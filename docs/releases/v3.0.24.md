# XX-WRT v3.0.24

## 修复

- 统一「设备」页终端名称、在线状态和设备来源的判定机制。无论登录预加载、概览自动轮询、设备页自动轮询还是手动刷新，都采用同一套 WeChatPush 终端快照合并规则。
- 当路由器已部署 WeChatPush 时，以 WeChatPush 对应 MAC 的明确 online/offline 状态为准。DHCP、ARP、无线关联和 AppFilter 只用于发现终端、补充 IP/IPv6/无线信号/设备类型；不能擅自将未被监控确认的终端标记在线。
- WeChatPush 返回的在线、离线、未知设备全部保留在「全部终端」列表中，不再仅将在线项纳入独立设备来源，减少 DHCP 短时变化导致的终端列表跳变。
- WeChatPush 单次读取失败、JSON 被短暂写入、服务状态读取失败时，90 秒内沿用同一台路由器最近一次成功的监控快照；保留终端名称、备注与状态，不回退为 ARP/Wi-Fi 判断。超过保护窗口或明确检测到监控服务停止后，历史状态变为「待确认」，不将旧在线数据无限当成实时在线。
- 单次 DHCP 接口失败时保留上次已知终端和地址，避免短暂的空结果清空列表。有效的空备注文件仍会清除被删除的备注。
- WeChatPush 已部署时跳过冗余的路由器端逐 IP ping/ARP 强制探测，减少刷新请求耗时与设备负担。
- 未部署 WeChatPush 的路由器继续使用原有 ARP/无线关联在线推断作为兼容回退。

## 验证

- 新增公共终端数据融合逻辑测试：监控在线/离线优先、未覆盖设备待确认、两轮连续失败、90 秒保护期、服务主动停止、备注清空、无监控兼容。
- 新增移动端界面回归：WeChatPush 监控快照短暂读取失败时，终端名称和在线数量保持不变；下一次有效监控快照能正常更新状态；只存在于 WeChatPush 的离线终端仍出现在全部列表。
