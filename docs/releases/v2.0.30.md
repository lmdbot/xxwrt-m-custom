# XX-WRT Material v2.0.30

## 新功能

- “应用 → 系统工具”新增独立的“软件包”管理页面，直接调用路由器现有 LuCI `package-manager-call`，不嵌入网页版，也不执行用户拼接的 shell 命令。
- 软件包列表提供“可用”“已安装”“更新”三个页签，展示名称、版本、大小、描述、已安装/可更新状态；支持名称、版本、描述搜索，默认 100 条分页和 LuCI 翻译包过滤（已过滤、全部、不显示）。
- 支持按包名或可信 HTTPS IPK 下载并安装，已安装软件包移除、单个软件包升级、刷新软件源列表，并展示操作执行日志和错误原因。
- 新增“上传软件包”：Android 文件选择器选取本地 IPK（较新 apk 后端使用 APK），通过 rpcd `file.write(base64:true)` 分块上传二进制文件，确认后安装，操作后清理临时文件。
- 支持编辑 opkg/apk 的主要软件源和主配置文件（仅固定白名单中的配置路径），显示实际可用文件，保存前提示风险，保存后需重新更新列表。
- 显示用于安装软件包的路由器磁盘空间占用（优先使用 LuCI `getMountPoints` 的 overlay 数据），提供刷新入口、操作结果弹窗、悬浮状态反馈。

## 优化

- 包管理调用复用 QWRT 自带 `/usr/libexec/package-manager-call`，支持 OpenWrt 的 opkg 文本包索引、已安装状态文件，以及较新版本 apk 的 JSON 包索引。包的具体依赖计算与安装合法性仍由路由器系统的包管理器处理。
- 高风险卸载与升级统一使用确认弹窗；批量升级额外要求手动输入“确认批量升级”，明确提醒固件核心包不宜直接批量升级。
- 通过专用 `RouterClient.callTimed` 为耗时的包管理命令设置最长 180 秒 RPC 等待时间；请求超时或网络断开时不误报成功，也不自动重试破坏性操作。
- 软件包名严格校验，安装 URL 仅支持 HTTPS，阻止将任意参数当作 shell 执行；配置文件读写只允许预定义路径；本地上传限制 32 MiB。
- 软件包模块使用懒加载：仅进入“软件包”应用时读取路由器的软件包索引，不影响首页和其他应用的加载速度。

## 修复

- 新增对包索引解析、数字版本比较、更新检测、非法安装参数、命令返回码、二进制分块上传和配置路径限制的单元回归测试。
- 在 UI 测试中增加软件包应用入口和分页/操作确认回归，避免发布时因新增功能未接入导航而漏测。

## 其他变更

- 版本从 2.0.29 升级到 **2.0.30**。
- 功能依赖路由器提供 LuCI 包管理工具、rpcd `file.exec` 和读写配置权限；缺少授权或软件源不可用时显示明确错误。
- 本地安装 APK（OpenWrt 25.12+）依赖路由器版本支持该安装方式；如果 apk 工具拒绝不可信本地包，需按固件自己的签名和仓库规则处理。QWRT opkg/IPK 为本次主要适配目标。
- 受 ubus 响应体大小限制，极大软件源目录在个别固件中可能需要 LuCI 的 cgi-io 流式查询后端；本版优先复用已安装系统包管理 RPC，不自动部署新的路由器侧服务。
