# Release 日志维护规范

每次发布新的正式版本时，创建与 `ui/material-prototype/package.json` 版本一致的 `docs/releases/vX.Y.Z.md`。**只写本次版本相较上一正式版本的变更**，历史变更应保留在各自的旧版本文件中。

按需使用如下章节，没有改动的类别可以省略：

- `## 新功能`：本次新增的能力。
- `## 优化`：性能、布局、交互与体验改进。
- `## 修复`：本版修复的问题。
- `## 其他变更`：升级提醒或必要的兼容性说明。

禁止在每版说明中重复粘贴 README 中的完整产品功能清单，也不要持续累积旧版本的更新历史。Android Release 工作流严格读取当前版本对应的文件；若该文件缺失或没有分类章节，停止发布。
