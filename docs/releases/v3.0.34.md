# XX-WRT v3.0.34

## 修复

- 终端列表成员改为 **QWRT 本轮发现的终端 ∪ 微信推送状态明确为 online 的终端**，按 MAC 合并。微信推送离线/未知记录、小米当前/历史库存、OpenAppFilter 单独记录均不能增加设备列表。
- 小米记录及 OAF 仅作为已入选终端的元数据来源：补充 2.4G / 5G / LAN、别名等信息。小米历史设备不会凭自身记录出现在终端列表。
- 在线判定优先级调整为：
  1. **微信推送在线** → 在线（即使小米显示离线）。
  2. 不在微信推送在线列表，且小米本轮返回**明确 online=0 / false** → 离线（即使 QWRT 邻居状态仍有在线记录）。
  3. 其他情况 → 根据 QWRT 自己的邻居、关联站点状态判断；证据不足则待确认。
- 当前小米接口以及历史接口的明确 offline 字段可提供**负面证据**，但小米 online=1 **不作为在线依据**；无 offline 标记的历史记录不推断为离线。
- QWRT 邻居状态单独存储，不再因路由侧微信推送覆盖而丢失；WeChatPush 当前文件读取失败、QWRT 本轮设备读取失败或 Wi-Fi 站点读取失败时，不拿上一次 App 快照冒充本轮发现的设备。
- 删除“已连接小米路由器，获取到 X 台设备”的常驻成功提示；成功关闭设置弹窗，不占用设备列表空间。异常仍显示错误提示。
- 设备页面的小米来源筛选数量仅统计列表内与小米匹配的终端，避免把小米历史库存直接计入设备列表总数。
- 微信推送监控不可用时，数量按实际本轮可用信息显示，状态说明同步更新。

## 验证

- 回归测试覆盖：仅 QWRT+微信推送在线记录入列、微信推送离线记录不独立入列、微信推送在线优先、小米明确离线优先、缺乏小米证据时 QWRT 上线/离线/待确认三态、历史在线标记隔离与当前在线覆盖。
- 小米管理访问链路和 QWRT RPC 后端未改动：升级 Android App 即可，不需要重装小米 RPC 扩展。
