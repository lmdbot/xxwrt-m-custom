# XX-WRT v3.0.18

## 修复

- 修复「工具 → 防火墙」状态长期显示「待确认」或「已配置（运行待确认）」的问题。原因是原版主要判断 `rc.list.firewall.running`：OpenWrt fw4/fw3 将规则写入内核后通常没有常驻进程，因此不能据此认定防火墙是否运行。
- 优先采用 LuCI 标准 ACL 允许的只读调用 `/usr/sbin/nft --terse --json list ruleset`，解析实际内核 `table inet fw4` 与挂载的 input/forward 等基链，明确显示「规则已加载」，并以绿色状态标识。
- 兼容旧版 fw3：如果未检测到有效 fw4 规则，使用 `/usr/sbin/iptables-save` 读取 fw3 区域链，避免因为无 nft 表而误判旧版防火墙。
- 将「开机启动已关闭」与「内核规则是否加载」分开判断；即使启动项关闭，但内核规则确实存在，仍如实显示「规则已加载」。
- 当两种内核规则均已可读且均未发现 fw4/fw3 规则时，提示「未检测到规则」；任一后端因 RPC 权限不足、版本差异或命令异常无法核实时，显示中性「无法核实」并给出在 LuCI 核查的说明，不把未知状态伪造成停止。
- 防火墙概览的 NAT 类型现在复用实际内核规则：明确区分真实 Full Cone NAT、普通源地址转换及「仅配置、内核未核实」；TCP 拥塞控制读取独立执行，不因防火墙规则读取受限而丢失。
- 全程仅使用固定参数的只读 RPC，不修改路由器配置或 ACL 权限。补充 fw4、fw3、未加载、权限不足及 NAT 分类的自动化测试。
