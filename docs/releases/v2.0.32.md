# XX-WRT Material v2.0.32

## 新功能

- 终端管理新增原生 **QWRT HQoS** 适配：通过 `hqos.status` / `hqos.get` 检测后端运行状态、已配置的客户端 MAC 规则和硬件能力，并通过 `hqos.set` 写入规则，与路由器 Web 管理页面共用后端。
- HQoS 终端限速使用 Web 端相同的 **kbps** 单位，支持独立上传和下载限制、IPv4/IPv6 共用 MAC 额度及 **0–65535** 并发连接数；**0 表示不限**，三项均为 0 可清除该 MAC 的规则。
- 终端详情新增“**HQoS 全局设置**”：管理启用状态、`auto` / `mtk-ppe` / `airoha-ppe` / `cpu` 后端和 QoS 接口。保存后通过固定命令 `/usr/sbin/hqos apply` 应用。
- 若全局 HQoS 原先关闭，保存任一非零终端限额将自动开启 HQoS；App 增加明确的二次确认弹窗。

- 终端限速支持**多 QoS 后端管理**：独立检测 HQoS、nft-limiter、EQOS、nft-qos，默认推荐已启用且运行中的可编辑后端，手动选择已有后端查看和编辑各自的规则。
- SQM/CAKE、QoSify 和 QoS Scripts 支持**只读发现与状态展示**，不误写成终端限速规则；各后端运行状态无法确认时明确区分“配置启用”和“运行中”。
- 多后端可能同时对流量整形时显示冲突提醒；为已有其他 QoS 服务的网络新增终端限额，或启用 HQoS 全局功能，需要明确确认风险。
- 切换管理后端会恢复该后端自己的值和单位：HQoS 为 MAC + kbps + 并发连接数，旧后端仍使用 IPv4 + Mbps，避免配置交叉覆盖。
- 新增 Playwright UI 场景覆盖 EQOS/HQoS 手工切换、独立规则读取、冲突确认和写入目标。

## 修复

- 修复 QWRT 已安装 `luci-app-hqos` 但 App 误提示不存在受支持的终端限速后端的问题。
- HQoS 的 MAC 规则不再误用原先按 IPv4 和 Mbps 管理的 EQOS / nft-qos / nft-limiter 写入流程。
- 严格按原生 HQoS 后端的 `capabilities.max_rate` 校验速率，校验单播 MAC、非负整数和连接数上限，阻止超限或无效参数写入。
- 支持检测后台权限不足、后端不支持和规则并发修改，并显示准确错误，不把 RPC 中的 `{error:...}` 误判为成功。
- 全局配置编辑会先检查未提交的 UCI 变更；应用失败时尝试恢复原来的启用状态、后端与接口配置并重新应用。
- 终端管理与 HQoS 逻辑回归扩展至 **25 项**，覆盖多后端识别、运行状态优先级、手动切换、只读后端、冲突确认及并发状态变化；原有终端管理测试保持通过。

## 注意

- 首次启用 HQoS 或切换 CPU/硬件后端可能影响流量转发及硬件加速，请确认 QWRT 当前的 offloading 配置与后端能力。HQoS 空规则状态下，`enabled=true` 不一定意味着引擎实际运行。
- 修改全局 HQoS 需要登录会话拥有 `uci hqos` 写权限和固定 `/usr/sbin/hqos apply` 的 `file.exec` 权限。
- 当前适配依据 QWRT 提供的 `luci-app-hqos 1-r6`、`hqos.manager` 和 `rpcd/hqos` 实际接口结构；未对真实路由器执行任何写入。发布前应在 QWRT 上验证应用与回滚。
