# XX-WRT Material v2.0.29

## 新功能

- “网络 → 接口”增加 OpenWrt 接口配置入口，在原有接口卡片中提供“配置 / 连接 / 断开”操作；保留 IPv4、IPv6、DNS、MTU、路由、运行时间等原有状态展示。
- 支持 UCI `network` 接口常用配置：开机自动启用、静态 IPv4、DHCP 客户端、PPPoE、DHCPv6、无地址模式、网关、DNS、默认路由、路由跃点数、部分 IPv6 静态及前缀分配参数。
- 支持 LAN 侧 DHCP 服务端配置：DHCPv4 启停、地址池起始偏移、地址数量、租期、DHCPv6 服务及 IPv6 RA 通告模式。DHCP 客户端（由上级分配地址）与 DHCP 服务端（本路由器向终端分配地址）独立配置，不再混淆。
- 通过 netifd `network.interface.<name>.up/down` 实现接口即时连接/断开。对 LAN、WAN、WAN6 等关键接口禁止即时断开，避免直接切断管理连接。

## 优化

- 通过 `uci.get` 读取 `network` 和 `dhcp` 原始配置，在编辑窗口中分为常规、IPv6/高级、DHCP 服务端三个页签。
- 保存时只修改本次指定的 UCI 字段，尽可能保留桥接、VLAN、拨号凭据和其他高级配置；PPPoE 密码不在 APP 中回显，留空表示保留原值。
- 配置应用使用 `uci.apply({ rollback: true, timeout: 90 })`，必须在联网正常后手动 `uci.confirm`，否则由 OpenWrt 定时回滚，降低更换网关、LAN IP 后失联的风险。禁止未设置回滚保护的盲目 `uci.commit`。
- 增加静态 IP、子网掩码、DNS、IPv6 地址、DHCP 地址池及租期输入校验；切换静态 LAN 接口为 DHCP 客户端时，自动停用该接口原有的 DHCP 服务端。
- 当前未配置的动态接口和 WireGuard、隧道等特殊协议保持只读，避免误覆盖高级网络设置。桥接/VLAN/无线绑定等复杂拓扑管理仍由 LuCI 完成。

## 其他变更

- 应用版本从 2.0.28 升级到 **2.0.29**。
- 新增网络接口配置单元测试和浏览器回归检查，不修改已有路由器的配置；所有实际变更仅在用户操作时经 RPC 执行。
- 部分网络操作需要路由器 RPC 账户具备 `uci` 对 `network`/`dhcp` 的读写与 `apply`/`confirm` 权限以及 netifd 接口控制权限。远程修改网络前建议保持另一个可用的恢复连接方式。
